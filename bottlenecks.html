8 Bottleneck tables

A bottleneck table answers a feasibility question: which level of the condition X each target of the outcome Y requires (Deja 2026b). Necessary Condition Analysis (NCA) reports the table for the CE-FDH ceiling, whose bottleneck at a target \(t_y\) is the lowest condition value among the cases that reach \(Y \ge t_y\) (Dul 2016). A condition value above the bottleneck satisfies the necessary condition at the target and leaves attainment open, because other constraints can hold the outcome down (Dul 2016; Deja 2026b).

8.1 The bottleneck of a tolerance-indexed frontier

Quantile Necessary Condition Analysis (QNCA) reports the bottleneck at a tolerance pi in (0, 1], which fixes the share 1 - pi of successful cases that may sit below the requirement (Deja 2026b). At a target \(y_j\) of an ordered outcome grid, the raw frontier takes the \(k_j\) cases with \(Y_i \ge y_j\) and returns the condition value of rank \(h_j = \max\{1, \lceil k_j (1 - \pi) \rceil\}\) among the \(k_j\) cases. The monotone envelope replaces each raw value by the running maximum over the lower targets, and the fixed scope sets the requirement to the upper condition bound \(x_{\max}\) above the largest observed outcome. The fitted frontier \(\tilde\varphi_\pi\) is linear between consecutive grid points. The bottleneck at the target \(t_y\) is the value of the fitted frontier at \(t_y\) (Deja 2026b):

\[ T_x(t_y; \pi) = \tilde\varphi_\pi(t_y). \]

At the selected tolerance, a condition level below \(T_x(t_y; \pi)\) falls short of the requirement for \(Y \ge t_y\), and a condition level above \(T_x(t_y; \pi)\) leaves attainment uncertain, because the condition is necessary for the target and other conditions also constrain the outcome (Deja 2026b).

8.2 The table of the synthetic dataset

The synthetic dataset of 1000 cases of the qnca repository has a condition and an outcome on a scale from 0 to 100, and the analysis fixes the scope at [0, 100] x [0, 100]. A grid of 101 outcome targets places every whole number from 0 to 100 on the grid, so the bottleneck at a whole-number target is a row of qnca()$bottleneck.

library(qnca)
d <- read.csv("https://raw.githubusercontent.com/MarekDejaUJ/qnca/main/data/qnca_dataset_n1000.csv")
scope <- c(0, 100, 0, 100)
strict <- qnca(d$X, d$Y, pi = 1, n_grid = 101, B = 0, scope = scope)$bottleneck
tolerant <- qnca(d$X, d$Y, pi = 0.95, n_grid = 101, B = 0, scope = scope)$bottleneck
table_10 <- data.frame(outcome_level = strict$outcome_level,
                       pi_1.00 = strict$X_required, pi_0.95 = tolerant$X_required)
table_10[table_10$outcome_level %% 10 == 0, ]

At pi = 1, the table holds the CE-FDH bottlenecks of NCA. At pi = 0.95, the requirement rises at the low and middle targets, from 7.02 to 17.29 at the target 20 and from 43.94 to 54.84 at the target 50, and both tolerances require 88.66 at the target 80. Above the largest observed outcome of 89.07, the fixed scope sets the requirement to 100 at both tolerances.

8.3 The account of each target

The function qnca_resolution() returns one row per target with the conditioning-set size k, the selected rank, the raw order statistic, the fitted requirement after the envelope, the flag inherited, the number below and the exception_share of successful cases strictly below the fitted requirement, and the resistance rank - 1 (Deja 2026b). The resistance counts the added cases that the raw requirement absorbs while the raw requirement stays at or above the lowest condition value of the original successful cases.

res <- qnca_resolution(d$X, d$Y, pi = 0.95, n_grid = 101, scope = scope)
all.equal(res$fitted, tolerant$X_required)
#> [1] TRUE
res[res$y %in% c(20, 40, 50, 60, 70, 80), ]
#>     y   k rank      raw   fitted inherited below exception_share resistance
#> 21 20 357   18 17.29273 17.29273     FALSE    17      0.04761905         17
#> 41 40 158    8 39.65527 40.13063      TRUE     8      0.05063291          7
#> 51 50  91    5 51.58989 54.83977      TRUE     5      0.05494505          4
#> 61 60  50    3 58.61763 58.61763     FALSE     2      0.04000000          2
#> 71 70  16    1 67.14035 71.07615      TRUE     1      0.06250000          0
#> 81 80   6    1 88.65579 88.65579     FALSE     0      0.00000000          0
res$y[which(res$raw == res$fitted[res$y == 50])]
#> [1] 48

At the target 20, 357 cases reach the target, the tolerance selects rank 18, and 17 successful cases, a share of 0.048, sit below the requirement. The resistance of 17 states that up to 17 added cases leave the raw requirement at or above the lowest condition value of the 357 original successful cases.

The selected rank grows with the conditioning set. At pi = 0.95, the rank exceeds 1 when more than 20 cases reach the target, since \(\lceil 0.05\,k \rceil = 1\) for \(k \le 20\). At the targets 70 and 80, 16 and 6 cases reach the target, the rank is 1, and the tolerant requirement rests on the minimum, as the strict requirement does. A report marks a tolerant bottleneck with rank 1 as limited by tail size, because too few cases remain to express the intended tolerance, and shows the selected rank or the conditioning-set size beside each important bottleneck (Deja 2026b).

At the target 50, the raw order statistic is 51.59 and the fitted requirement is 54.84, the raw requirement of the target 48, which the envelope carries upward. The inherited value repeats a requirement established at a lower target, so a report marks the bottleneck as inherited (Deja 2026b). Inheritance has a cost: at the target 50, 5 of the 91 successful cases sit below the fitted requirement, a share of 0.055 that exceeds the tolerance of 0.05. The excess arises because the exceptions admitted at the lower target concentrate among the cases that reach the higher target (Deja 2026b).

8.4 Required levels at decision targets

A bottleneck table for a decision lists the required level at the targets of the decision, with the conditioning-set size and the selected rank beside each requirement and with flags for inherited and tail-limited bottlenecks (Deja 2026b). The table holds the targets 20, 40, 60 and 80 at the tolerances 1.00, 0.95 and 0.90.

targets <- c(20, 40, 60, 80)
decision <- do.call(rbind, lapply(c(1, 0.95, 0.90), function(p) {
  r <- qnca_resolution(d$X, d$Y, pi = p, n_grid = 101, scope = scope)
  r <- r[r$y %in% targets, ]
  data.frame(target = r$y, pi = p, k = r$k, rank = r$rank,
             required = round(r$fitted, 2), inherited = r$inherited,
             tail_limited = p < 1 & r$rank == 1)
}))
decision <- decision[order(decision$target, -decision$pi), ]
rownames(decision) <- NULL
decision
#>    target   pi   k rank required inherited tail_limited
#> 1      20 1.00 357    1     7.02     FALSE        FALSE
#> 2      20 0.95 357   18    17.29     FALSE        FALSE
#> 3      20 0.90 357   36    25.52     FALSE        FALSE
#> 4      40 1.00 158    1    28.06     FALSE        FALSE
#> 5      40 0.95 158    8    40.13      TRUE        FALSE
#> 6      40 0.90 158   16    48.70      TRUE        FALSE
#> 7      60 1.00  50    1    56.06     FALSE        FALSE
#> 8      60 0.95  50    3    58.62     FALSE        FALSE
#> 9      60 0.90  50    5    60.39      TRUE        FALSE
#> 10     80 1.00   6    1    88.66     FALSE        FALSE
#> 11     80 0.95   6    1    88.66     FALSE         TRUE
#> 12     80 0.90   6    1    88.66     FALSE         TRUE

The required level rises with each step down in tolerance at the targets 20, 40 and 60. At the target 20, the requirement moves from 7.02 to 17.29 and 25.52, at the target 40 from 28.06 to 40.13 and 48.70, and at the target 60 from 56.06 to 58.62 and 60.39. Three tolerant requirements, at the target 40 for both tolerances and at the target 60 for pi = 0.90, are inherited from lower targets. At the target 80, 6 cases reach the target, every tolerance selects rank 1, and all three tolerances require 88.66. The two tolerant bottlenecks at the target 80 are therefore limited by tail size.

The requirement is a floor of feasibility. At pi = 0.95, the target 60 requires 58.62, and the count of cases at or above the requirement shows how many of the cases reach the target.

req_60 <- res$fitted[res$y == 60]
above <- d$X >= req_60
c(cases_above = sum(above), reach_target = sum(above & d$Y >= 60))
#>  cases_above reach_target 
#>          420           48

Of the 420 cases at or above the requirement, 48 reach the target 60. A case above the floor meets the necessary condition for the target, and the outcome of the case depends on the other conditions of the outcome (Dul 2016).

8.5 Comparison with the stored table

The file bottleneck_comparison_n1000.csv of the repository stores the bottlenecks of the same dataset at the targets 0, 20, 50, 70 and 80, with the CE-FDH bottlenecks of the R package NCA rounded to three decimals (Dul 2026).

stored <- read.csv("https://raw.githubusercontent.com/MarekDejaUJ/qnca/main/data/bottleneck_comparison_n1000.csv")
stored[, -(1:2)]
#>   outcome_level dul_ce_fdh qnca_pi1_00 qnca_pi0_95 qnca_pi0_90
#> 1             0      0.082  0.08246168    4.887538    9.422986
#> 2            20      7.023  7.02333709   17.292731   25.518651
#> 3            50     43.935 43.93500619   54.839774   58.617630
#> 4            70     67.140 67.14035242   71.076154   77.668868
#> 5            80     88.656 88.65579137   88.655791   88.655791
own <- sapply(c(1, 0.95, 0.90), function(p) {
  b <- qnca(d$X, d$Y, pi = p, n_grid = 101, B = 0, scope = scope)$bottleneck
  b$X_required[match(stored$outcome_level, b$outcome_level)]
})
max(abs(own - as.matrix(stored[, c("qnca_pi1_00", "qnca_pi0_95", "qnca_pi0_90")])))
#> [1] 4.973799e-13
all(round(own[, 1], 3) == stored$dul_ce_fdh)
#> [1] TRUE

The computed bottlenecks differ from the stored values by at most 5e-13, and the strict column rounded to three decimals equals the CE-FDH column of NCA at every stored target. The bottleneck table of NCA reports the attained levels, so the stored comparison ends at the target 80, whereas the fixed scope of QNCA sets the requirement to 100 at the levels from 90 upward (Deja 2026b).

8.6 The same table in Python and Julia

The Python package qnca and the Julia package QuantileNecessity return the same conditioning-set sizes, ranks and requirements at the decision targets.

from urllib.request import urlopen
import numpy as np
from qnca import qnca_resolution

url = "https://raw.githubusercontent.com/MarekDejaUJ/qnca/main/data/qnca_dataset_n1000.csv"
X, Y = np.loadtxt(urlopen(url), delimiter=",", skiprows=1, unpack=True)
scope = (0.0, 100.0, 0.0, 100.0)
for pi in (1.0, 0.95, 0.90):
    res = qnca_resolution(X, Y, pi=pi, n_grid=101, scope=scope)
    rows = np.isin(res.y, [20.0, 40.0, 60.0, 80.0])
    print(pi, res.k[rows], res.rank[rows], np.round(res.fitted[rows], 2))
#> 1.0 [357 158  50   6] [1 1 1 1] [ 7.02 28.06 56.06 88.66]
#> 0.95 [357 158  50   6] [18  8  3  1] [17.29 40.13 58.62 88.66]
#> 0.9 [357 158  50   6] [36 16  5  1] [25.52 48.7  60.39 88.66]
using QuantileNecessity, Downloads, DelimitedFiles

url = "https://raw.githubusercontent.com/MarekDejaUJ/qnca/main/data/qnca_dataset_n1000.csv"
data = readdlm(Downloads.download(url), ',', Float64; skipstart = 1)
X, Y = data[:, 1], data[:, 2]
scope = (0.0, 100.0, 0.0, 100.0)
for p in (1.0, 0.95, 0.90)
    res = qnca_resolution(X, Y; pi = p, n_grid = 101, scope = scope)
    rows = findall(in([20.0, 40.0, 60.0, 80.0]), res.y)
    println(p, " ", res.k[rows], " ", res.rank[rows], " ", round.(res.fitted[rows]; digits = 2))
end
#> 1.0 [357, 158, 50, 6] [1, 1, 1, 1] [7.02, 28.06, 56.06, 88.66]
#> 0.95 [357, 158, 50, 6] [18, 8, 3, 1] [17.29, 40.13, 58.62, 88.66]
#> 0.9 [357, 158, 50, 6] [36, 16, 5, 1] [25.52, 48.7, 60.39, 88.66]
